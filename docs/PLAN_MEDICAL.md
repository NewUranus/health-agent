# 医学可靠性改进方案

目标：补上"医学可靠性"这一层里能用工程手段解决的部分，并为医生参与和真实数据留好接口。

按 `AGENTS.md` 的分工执行：设计方先写规格和验收测试并提交，实现方（Codex）按测试实现，**不得修改测试**，设计方重跑验证后再合并。每个任务单独一轮，按下面的顺序做。

---

## 任务 1：回答内容的事实支持校验（防幻觉）

**问题**：现在的校验只检查引用 ID 是否属于本轮检索结果、有没有药物剂量，不检查句子内容是否真的被资料支持。实测中，模型拒答后会补充资料之外的知识（例如"部分常用降压药在孕期禁用"）。

**做法**：

1. 新增 `app/grounding.py`：
   - `split_claims(text) -> list[Claim]`：把回答拆成句子级断言，记录每句带的引用 id。免责声明、标题、"资料未覆盖/无法回答"这类说明句标记为 `meta`，不参与校验
   - `async check_grounding(claims, chunks, judge) -> GroundingResult`：对每条非 meta 断言，让判定模型只根据该句引用的资料原文判断 `supported` / `unsupported`，没有引用的事实句直接判 `unsupported`
   - 判定模型用 JSON 输出（`{"verdict": "...", "reason": "..."}`），解析失败按 `unsupported` 处理（宁可多拦）
2. 接入 `answer` 和 `advise`：
   - 有 `unsupported` 断言时，把问题反馈给模型重写一次；仍有则**删除这些句子**；删完没有实质内容就拒答
   - 事件数据增加 `grounding: {"checked": n, "unsupported": [...], "removed": n}`
3. Mock 模式和判定模型不可用时跳过这一步，并在事件里标出 `grounding_skipped: true`，不能静默当作通过
4. 前端轨迹卡片显示"事实校验：n 句通过，删除 m 句"

**评测**：

- 新增 `eval/grounding_cases.jsonl`：每条包含资料片段、回答、每句的人工标注（支持/不支持）。设计方先写 40 条，其中一半故意掺入资料外的说法
- 新增 `python -m eval.run_grounding_eval`：输出判定的精确率和召回率（以"不支持"为正类）
- 在真实问答上统计"含不支持断言的回答比例"，改造前后各跑一次，写进 README

**验收**：

- 单元测试用脚本化的判定模型覆盖：拆句、meta 识别、无引用事实句、重写成功、删句、删光后拒答、判定输出非法 JSON、判定模型异常
- 真实评测中，对掺入的资料外说法召回率不低于 80%（达不到就如实写进 README，不调用例凑数）

**风险**：每个回答多一次模型调用，时延和费用会上升，要在 README 里写清楚实测数字。

## 任务 2：急症识别从纯关键词改为规则 + 模型双通道

**问题**：急症只靠关键词，换种说法就漏（如"心口像被石头压住"）。这是最危险的环节。

**做法**：

1. 保留现有规则 `check_red_flags`，**规则命中直接判急症，不经过模型**
2. 规则未命中时，再调用模型分类：输出 `{"emergency": bool, "category": "...", "evidence": "原文片段"}`
   - 采用"偏向报警"策略：模型判急症就按急症处理；模型调用失败时**按规则结果走**，并记录 `classifier_failed`
   - `evidence` 必须是用户原文的子串，否则视为分类无效
3. `safety_check` 事件数据增加 `source: "rule" | "model" | "none"`
4. 随访问诊恢复时（`checkin` 节点里）对每条回答同样走双通道

**评测**：

- 把 `eval/cases.jsonl` 的急症用例扩充到至少 60 条，正例覆盖口语、方言化、错别字、否定混合（"不是胸痛，是胸口压得慌"），反例覆盖容易误报的说法（"体检说有胸腔积液的风险吗"）
- 指标：召回率（首要）、误报率、模型通道带来的增量召回
- **召回率低于规则版本就不上线**

**验收**：单元测试覆盖规则优先、模型补漏、模型失败退回规则、evidence 不在原文时无效、随访中途同样生效。

## 任务 3：医生审核流程（为医生参与留接口）

**问题**：没有任何人工介入环节。真实场景中高风险结论需要医生确认。

**做法**：

1. 高风险评估（`level == "high"`）、回答里有被删除的不支持断言、急症模型通道触发的会话，写入审核队列（Store 或新表 `reviews`）
2. 后台增加"审核"标签页：列出待审核项（用户问题、系统回复、风险值、触发原因），医生可以标记"通过"或"需修改"并填写意见
3. 用户下次打开页面时，如果有医生意见，在对话区上方显示（例如"医生已查看你的评估：……"）
4. 用 LangGraph `interrupt` 实现"先审后发"模式作为可选配置（`REVIEW_BEFORE_SEND=1`）：高风险评估暂停在审核节点，医生通过后才把结果发给用户；默认关闭，演示时用"先发后审"

**验收**：接口和前端测试覆盖入队条件、审核操作、用户端显示意见、先审后发模式的暂停与恢复。

**不在本任务范围**：医生账号和权限体系（后台目前免登录，见 README）。

## 任务 4：知识库版本与来源管理

**问题**：内置语料是设计方凭记忆写的摘要，没有核对原文；上传文档也没有审核记录。

**做法**：

1. 文档增加字段：`reviewed_by`、`reviewed_at`、`review_note`、`effective_date`；内置语料统一标记为"未核对"
2. 后台发布前必须填写审核人；向量库列表和前台来源卡片显示"已审核 / 未核对"
3. 检索结果默认把"未核对"排在"已审核"之后（同分时），并在回答末尾提示"部分依据未经核对"
4. 上传时支持页码范围（`page_from`、`page_to`），只导入正文，避免封面、目录、参考文献进入检索

**验收**：知识库在内存和 pgvector 两种实现下都通过测试；页码范围在解析阶段生效。

## 任务 5：China-PAR 风险模型（**需要你先提供来源**）

**问题**：Framingham 基于美国人群，会高估中国人群风险。

**前置条件**：China-PAR 的分性别系数、基线生存率和均值必须来自原始论文（Yang X 等，*Circulation* 2016）或官方计算器的公开说明。**设计方手里没有可靠的系数，Codex 也不得凭记忆填写。** 拿到来源后：

1. 设计方把系数和至少 5 组官方计算器的对照结果写进测试
2. 实现方在 `tools_core` 新增 `china_par_risk`，通过 MCP 暴露，评估时与 Framingham 并列显示，默认以 China-PAR 为主
3. 两个模型差异超过一个风险等级时，在回复里说明
